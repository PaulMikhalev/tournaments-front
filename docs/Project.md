# Tournaments Frontend Project

## 📋 Обзор проекта

**Tournaments Frontend** - это современное веб-приложение для организации и участия в киберспортивных турнирах, построенное на Nuxt 4 с использованием Vue 3 и TypeScript.

## 🎯 Основные возможности

### Для пользователей:
- **Просмотр турниров** - каталог активных и предстоящих турниров
- **Детальная информация** - подробные страницы турниров с сеткой, участниками, правилами
- **Профиль пользователя** - статистика, история участия, достижения
- **Регистрация на турниры** - простое участие в соревнованиях

### Для организаторов:
- **Создание турниров** - интуитивная форма с настройками
- **Управление турнирами** - контроль участников и результатов
- **Мониторинг активности** - отслеживание прогресса турниров

## 🏗️ Архитектура проекта

### Технологический стек:

### Специальные режимы (UI/UX):

#### Soulcalibur VI — «Игра на вылет»

UI/UX требования:
- На странице турнира `TournamentOverview` отобразить раздел «Ростер персонажей» для каждого игрока: 8 слотов (иконка/имя), статус `жив`/`мёртв`, отметка «Ебыч» и источник `выбор`/`рандом`.
- Кнопки действий для организатора (или капитана): «Выдать рандом», «Подтвердить выбор персонажа», «Зафиксировать смерть/воскрешение» с безопасными подтверждениями.
- Индикатор этапа турнира (Этап 1 BO3, Этап 2 BO7) и доступность участия для игрока (подсказка, если живых персонажей ≤ 4).
- Таймлайн событий матча: сохранённый персонаж, смерть, повторный выпадение, возврат попытки, воскрешение.

Правила (отображение/валидация на фронтенде):
- Счётчик оставшихся попыток рандома (изначально 6); при повторном выпадении ранее сохранённого — попытка не тратится.
- Поведение кнопки «Выдать рандом» зависит от состояния ростера/счётчика.
- Нельзя участвовать в Этапе 1, если у игрока ≤ 4 «живых» персонажей.
- Переключение на Этап 2 при условии, что участвовать может только один игрок (серверный флаг `currentStage`).

API интеграция (ожидаемые эндпоинты):
- `POST /tournaments/:id/sc6/roster/init` — инициализация 8 слотов игрока (Ебыч, выбранный, 6 рандомов — пустые слоты до выдачи).
- `POST /tournaments/:id/sc6/random` — выдать рандом персонажа, применить правила повторов/воскрешений.
- `POST /tournaments/:id/sc6/pick` — зафиксировать выбранного персонажа.
- `POST /tournaments/:id/sc6/match-events` — события боя: смерть, воскрешение; обновляет ростер и счётчик.
- `GET /tournaments/:id/sc6/state` — текущее состояние: этап, доступность участия, ростеры.

## 🔌 Интеграция с API

- Базовый URL API: хранится в `runtimeConfig.public.apiBase` (по умолчанию `http://localhost:3001`).
- Плагин `app/plugins/api.ts` предоставляет `$api` на базе `$fetch`:
  - Автоматически подставляет `baseURL` и `Content-Type: application/json`.
  - Вставляет `Authorization: Bearer <token>` из `localStorage.access_token`.
  - Включает `credentials: 'include'` для работы с cookie при необходимости.

### Аутентификация
- Эндпоинты: `/auth/register`, `/auth/login`, `/auth/me`, `/auth/logout`.
- После успешного `login/register` токен сохраняется в `localStorage.access_token`.

### Турниры
- Список: `GET /tournaments`
- Детали: `GET /tournaments/:id`
- Создание: `POST /tournaments`

Пример использования в компонентах доступен в `LoginForm.vue`, `RegisterForm.vue`, `TournamentsList.vue`, `pages/tournaments/[id].vue`, `pages/tournaments/create.vue`.
